# OpenDev Elite · 账号登录与成员管理

适用于 v0.8.0，SQLite schema 6。

## 直接登录

新工作空间默认管理员账号：**OpenDev**，密码：**123456**。Windows 访问 `http://127.0.0.1:8765/#team-login`；Docker Compose 默认访问 `http://127.0.0.1:8780/#team-login`。

登录页只提供账号密码登录和兼容登录方式，不再提供“创建管理员”和公开“注册成员”。可切换密码显示、使用键盘提交，错误会直接显示在表单内。账号不区分大小写，后台规范化存储为 `opendev`，显示名称为 OpenDev。

管理员仅在账号库尚未初始化且没有账号时自动创建一次。重启、升级或重建容器不会覆盖已修改的密码，也不会恢复被停用或删除的管理员。已有账号的 v0.5 安装保留原来的账号和密码，不额外添加默认管理员。

## 后台新增成员

1. 管理员登录，打开“成员与权限”，点击“新增成员”。
2. 填写账号、显示名称、初始密码和确认密码，至少选择一个角色。
3. 点击“创建成员”。成功后账号立即可用，管理员将账号和密码告知本人。

账号为 3–64 位字母、数字或 `_.@-`，显示名称为 1–80 个可见字符。新成员密码与修改后的密码为 6–128 个字符；OpenDev 的初始密码为 123456。页面与接口都验证输入，重复用户名会拒绝创建。创建接口只允许管理员，写操作需要 CSRF 和幂等键。

可按职责分配技术审核、项目运营、赞助审批、Credits 执行、质控审计或管理员。管理员不能停用或降权最后一位启用的管理员；同一笔赞助的审批人和执行人仍须分开。角色、状态和密码变更使所有旧会话在下一次请求时失效。旧版待审批账号保留，可继续审批授权。

需要加入团队或忘记密码的成员联系管理员，网站没有公开注册或邮件找回流程，也不会自动向成员发送消息。

## 修改与恢复密码

- 本人修改：打开“账号设置”，输入当前密码、新密码和确认密码，保存后重新登录。
- 管理员重置成员密码：在成员卡片中展开“重置此成员的密码”，输入新密码并保存。
- 管理员忘记密码：具有本机文件访问权限的部署者可使用交互恢复命令。

```powershell
python -I -m worker.accounts reset-password --db "实际部署目录/worker.db" --username OpenDev
```

```sh
docker compose exec api python -I -m worker.accounts reset-password --db /var/lib/opendev-elite/worker.db --username OpenDev
```

命令交互输入新密码，保留角色和启用状态；不会重新设置为初始密码。可替换为其他实际用户名。

## 存储与兼容

密码使用随机盐和 PBKDF2-HMAC-SHA256（600,000 次），不在数据库中存明文，成员接口不返回密码或摘要。浏览器使用 HttpOnly / SameSite Cookie，写请求校验精确 Origin 和 CSRF，HTTPS 使用 Secure Cookie。密码不写入浏览器本地存储。密码登录保留限流与计算并发限制，账号总数上限为 10,000。

旧“访问凭证”是角色 Token，现折叠在兼容登录入口。Agent 继续使用专用 Token。旧 Token 仍由服务端身份配置管理，停用同名密码账号不会撤销配置中的 Token；已有 SSO 继续兼容。

## 升级

v0.5.x → v0.6.1 将 schema 5 迁移为 schema 6，增加入选评估和档案译文历史，保留原账号与业务记录。更早版本按迁移顺序升级。先备份 SQLite 和配置，停止旧进程后切换新版。账号随原数据库和数据卷持久化。

Docker 如设置了镜像版本，将 `.env` 的应用与网关版本改为 `0.6.1`，执行：

```sh
docker compose stop gateway api worker
docker compose up -d
```
