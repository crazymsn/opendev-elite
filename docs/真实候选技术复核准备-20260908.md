## 1. ReactantServer.jl：优先核查推理服务的执行边界

- **固定版本**：`37c947b36a81384e70242d4784d40ab77a84fdcc`。
- **场景**：仓库提供 Julia 推理服务、客户端、网关及节点组件，属于推理与 Agent 基础设施候选。应围绕一个真实下游调用工作流评测。架构定位来自 [README](https://github.com/EnzymeAD/ReactantServer.jl/blob/37c947b36a81384e70242d4784d40ab77a84fdcc/README.md)。
- **已查看证据**：新采样覆盖三个 Julia 服务入口，旧采样只覆盖 Python 导出示例。[服务入口](https://github.com/EnzymeAD/ReactantServer.jl/blob/37c947b36a81384e70242d4784d40ab77a84fdcc/packages/ReactantServer/src/server.jl)组装运行时和调度，并明确提示执行超时配置尚无执行中 watchdog；需要实际验证取消、超时和资源回收行为，不能仅因存在超时字段认定可控。
- **维护依据**：不能只采用最近一次版本号更新。[8 月 30 日的客户端变更](https://github.com/EnzymeAD/ReactantServer.jl/commit/a5981adbaad1351d1889f04fae368faeabd6eb9b)实际修改内联输入的原始字节传输，并增加相关测试，是可复核的实质交付线索。
- **证据局限**：[采到的测试](https://github.com/EnzymeAD/ReactantServer.jl/blob/37c947b36a81384e70242d4784d40ab77a84fdcc/packages/ReactantServer/test/test_bert_text.jl)主要检查分词与张量处理；不能代表服务端端到端验证。[测试工作流](https://github.com/EnzymeAD/ReactantServer.jl/blob/37c947b36a81384e70242d4784d40ab77a84fdcc/.github/workflows/_test.yml)是供其他工作流调用的 CPU 测试配置；本次没有核验具体 CI 运行结果。
- **下一步**：补读调度和传输链路，准备已知输出的小模型；通过自有 Agent 验证正常推理、错误形状、超时取消和工作进程重启。先确认 Julia、模型及计算环境；GPU 性能结论须另有匹配硬件下的对照。

**当前建议**：进入负责人技术复核准备；完成剩余核查前不登记入选或技术通过。若缺运行环境，记录评测暂缓。

## 2. VISOR-serve：优先核查工具调度与依赖隔离

- **固定版本**：`6341f64b4ba72f4a607f3443bb9c555f3aece7e6`。
- **场景**：[README](https://github.com/DCBIA-OrthoLab/VISOR-serve/blob/6341f64b4ba72f4a607f3443bb9c555f3aece7e6/README.md)描述通过 HTTP 暴露工具、为工具保留各自依赖环境的服务。可先用通用工具评测 Agent 调用，不以临床效果作为此轮目标。
- **已查看证据**：新样本覆盖 [API 入口](https://github.com/DCBIA-OrthoLab/VISOR-serve/blob/6341f64b4ba72f4a607f3443bb9c555f3aece7e6/server/main.py)和 [子进程调度](https://github.com/DCBIA-OrthoLab/VISOR-serve/blob/6341f64b4ba72f4a607f3443bb9c555f3aece7e6/server/execution/dispatch.py)，替代原有基准测试样本。代码为执行路由设置鉴权依赖，并在工具子进程环境中移除服务 API_TOKEN，包含执行超时及进程组清理逻辑；这些实现仍需运行验证。独立 virtualenv 解决依赖冲突，本身不能证明操作系统层面的安全隔离。
- **维护依据**：[9 月 3 日修复](https://github.com/DCBIA-OrthoLab/VISOR-serve/commit/62dd3063f257874f7c363b6d9401ac1954fab08f)移除示例工具对 API 环境中 pandas 的依赖，改用标准库 CSV 处理，并增加导入约束检查；这比合并提交数量更能说明维护内容。
- **下一步**：用两个依赖版本不同的简单测试工具检查工具发现、参数校验、结果取回、失败语义和超时后的残留进程；再由自有 Agent 串联调用。使用合成数据，核查文件访问范围和凭证继承；本次不作医疗效果或合规结论。

**当前建议**：进入负责人技术复核准备；仍需核查权限实现、完整工具执行链和实际部署条件，不登记审核通过。

## 3. templ8c：先区分参考模板校验与外部系统验收

- **固定版本**：`dff5fd76fa72da0cb553e0227e53df5fa2820dc1`。
- **场景**：面向模型工具调用模板的开发者检查工具，有可核查的最小实现。可用于研究模板差异，但现有能力范围必须讲清楚。
- **已查看证据**：[Checker](https://github.com/SuperMarioYL/templ8c/blob/dff5fd76fa72da0cb553e0227e53df5fa2820dc1/src/templ8c/checker.py)分离加载、渲染、比较，也提供外部模板字符串检查入口。[比较器](https://github.com/SuperMarioYL/templ8c/blob/dff5fd76fa72da0cb553e0227e53df5fa2820dc1/src/templ8c/comparator.py)的 schema 检查主要检查名称和字段子串，不等于完整 JSON 结构、参数类型或语义校验。
- **能力边界**：[CLI](https://github.com/SuperMarioYL/templ8c/blob/dff5fd76fa72da0cb553e0227e53df5fa2820dc1/src/templ8c/cli.py)的 check 当前检查内置参考模板；传入 server 选项也明确提示尚未实现服务探测。[测试文件](https://github.com/SuperMarioYL/templ8c/blob/dff5fd76fa72da0cb553e0227e53df5fa2820dc1/tests/test_checker.py)包含错误 wrapper 的负例，但不能由此推断真实服务兼容性。本次未运行这些测试。
- **维护局限**：本次 90 天提交样本为同一天的初始实现、构建清理和站点增加。历史短不是排除理由；这些记录还不足以独立证明持续维护。需继续观察实质修复、发布或公开回应。
- **下一步**：为正常外部模板和有意破坏的模板预先定义负例，覆盖字段仅出现在普通文本、错误 JSON 和参数类型不匹配。以库入口验证外部模板，另行核查 CLI 的机器可读输出需求；不要把尚未实现的服务器探测当作产品已交付能力。

**当前建议**：维护连续性和目标任务尚待补证据，倾向暂缓观察；不能据此认定项目废弃，也不以零 Stars 或新项目身份排除。
