# v0.2 开发交付说明

本轮按代码工程、架构与独立质控三个角色并行实施，由主任务整合和回归。交付包括可安装的 Python 包、CLI、团队 JSON API、原爬虫整合、Agent 协议、Credits 适配、运行入口、测试和手册。没有注册长期任务、对外联系作者或发放真实 Credits。

## 已实现的技术路径

| 阶段 | 实现与控制 |
| --- | --- |
| 发现与采集 | 原 fetcher/userinfo 接入 Pipeline；全球配置检索、稳定 ID、增量刷新、限流退避、队列租约、部分覆盖报告 |
| 第一轮 | 工程/维护/文档证据；完整快照、SHA 和有效期检查；人工审核结论 |
| 第二轮 | 人/Agent/both 体验任务；真实结果结构；Agent 身份、租约、run_id 与摘要绑定；人工复核通过 |
| 联系与访谈 | 两轮门槛、维护者确认、草稿、联系记录、拒绝与去重、同项目访谈；不自动发送消息 |
| 赞助决定 | 证据与审批记录、金额和日期校验、撤回阻断后续写入；工程师/创业者画像由访谈支持 |
| Credits | 基于指定源码版本的接口适配；审批/执行身份隔离、服务配置写开关、提供方绑定、未知结果只读对账 |
| 复盘 | 确认已领取且额度吻合才记 issued，生成复盘待办；阶段/失效体验/可联系候选报告 |
| 服务与运维 | Bearer 摘要配置、角色授权、幂等事务、TLS、数据库 v3 迁移、tick/run/doctor、备份和 wheel 包 |

原爬虫复用细节见 [原爬虫整合说明](原爬虫整合说明.md)，服务接入见 [服务端 API 手册](服务端API手册.md)。长期架构背景见 [自动化开发计划](自动化开发计划.md)，原 v0.1 阶段的实现描述不能用来判断当前代码状态。

## 关键修复

质控和架构复核修复了失效任务继续执行、队列租约过期后写入、同 SHA 重审后旧任务提交、跨项目访谈、撤回审批后继续发放、外部并发响应覆盖已完成台账，以及过期任务挤占 Agent 队列等问题。Docker 封装限制凭证继承、日志/结果/引用证据大小，拒绝路径穿越和文件链接，并在超时后验证清理。

本轮还对真实 HTTP 和 HTTPS 连接进行验证：权限、请求格式、幂等并发、Agent 租约与结果绑定，以及空闲 TLS 握手不阻塞其他连接。独立质控的详细边界见 [独立质控报告](独立质控报告.md)。

## 运行与交付边界

```powershell
python -m unittest discover -s tests -v
python main.py init
python main.py doctor
python main.py tick --config config/discovery.json --max-jobs 20 --out artifacts/operations
python main.py serve --config config/service.local.json
```

正式启动 serve 前需要生成独立身份凭证，不能直接使用示例配置。数据库默认位于本机应用数据目录。API 与采集工作进程分别运行，使用同一台机器上的 SQLite。

代码验证不等于外部业务验收。剩余事项有明确依赖：

1. Credits：真实部署地址、活动 slug 与到期设置、PAT、测试领取账户，再执行创建邀请→领取→只读对账验收。
2. Agent：已审核并固定 digest 的镜像或团队自有隔离环境、准确 SHA 的源码/依赖、所需模型与测试凭证、远程证据存储。当前机器无 Docker，容器调度测试使用 mock；真实本机子进程和文件边界测试已执行。
3. 长期运行：选定主机、TLS/反向代理、进程托管、密钥 ACL、备份和监控接收方；没有自动安装常驻服务。
4. 业务验收：真实候选的两轮审核、联系与访谈，需要团队执行。SSO、浏览器审核界面和多租户服务未包含在本轮实现中。

离线 Docker 模式不会自行克隆源码或访问在线模型。8 MiB 日志、1 MiB 结果和 64 MiB 引用证据上限不能替代整个输出卷的操作系统硬配额；生产 runner 应使用专用执行节点和容量配额。

最终测试和安装包验证结果见 [验证记录](验证记录.md)。
