# OpenDev Elite 团队操作指南

v0.8.0 使用居中单表单登录页，保留默认管理员登录和后台统一创建成员。Windows 直接部署访问 http://127.0.0.1:8765，[Docker Compose 部署](DockerCompose部署.md) 默认访问 http://127.0.0.1:8780。新工作空间使用 OpenDev / 123456 登录，管理员在“成员与权限 → 新增成员”填写账号资料并分配角色。没有公开注册入口。详细步骤见 [账号注册与授权](账号注册与授权.md)。原 Token 登录保留在“其他登录方式”折叠入口，配置了 OIDC 时也可使用团队单点登录。

## 先选择正确身份

| 身份 | 使用入口 | 主要职责 |
| --- | --- | --- |
| relationship-operator | 候选项目、联系与访谈、采集与运行 | 导入、分配、维护关系确认、联系记录、访谈 |
| technical-reviewer | 候选项目、产品体验 | 技术复核、体验设计、人类体验记录、第二轮审核 |
| funding-approver | 候选项目的赞助审批、赞助台账 | 依据访谈审批并记录条款 |
| credits-operator | 赞助台账 | 核对计划、创建已批准邀请、查询到账 |
| quality-auditor | 概览、赞助台账、操作审计 | 检查流程、证据及历史操作 |
| experience-agent | 专用 API / agent-poll | 自动领取、执行、回传 Agent 体验；不用人工后台 |

团队成员由管理员创建独立账号并分配以上职责；表中身份名同时对应兼容 Token 的六个独立角色示例。日常使用账号密码登录，无需分发 Token。角色可以组合，但审批与真实发放仍必须由不同 actor 执行，Agent 不能混用人工角色。

完整入选、暂缓及排除定义见 [项目入选与排除标准](项目入选与排除标准.md)。维护更新时间不能单独作为持续维护依据；资料不足先暂缓。

## 从项目到赞助

1. **导入候选**。运营人员在“候选项目”点击“导入项目”，每行填写一个 GitHub 仓库。采集进程读取公开资料，保留稳定 ID、Commit 和完整性说明。工作台不会把刚导入的项目显示为审核通过。
2. **入选与第一轮复核**。打开项目，设置目标用户和负责人，先在“入选评估”填写五项 0–4 分质量评分及逐项依据：需求 20%、工程 25%、维护 20%、差异化 20%、可评测性 15%。总分至少 80，每项至少 3；维护至少有过去一年内两个不同日期及两个对应来源。表单实时算分，保存时服务端重算并验证。低分或证据不足先暂缓，旧标准记录需重评。当前有效入选后，审核人查看仓库证据、源码和文档，记录结构、维护、文档三个维度的依据。选择通过、待观察或未通过。通过需要完整的当前版本快照；搜索命中或 Stars 数量不能代替判断。
3. **真实体验**。创建场景、成功标准、输入、环境与时间预算。面向人的产品由团队体验并在“产品体验”记录实际结果；Agent 产品由专用执行器领任务、上传真实文件并回传结果，不能用人工通用入口冒充 Agent。打开 Agent 体验的“详情”可下载已完成上传的证据，核对文件摘要和内容。混合产品需要两类体验。
4. **第二轮复核**。审核人引用当前第一轮之后完成的体验 ID，记录真实问题、使用结果、差异化和潜力。默认列出的成功体验 ID 仅供选择，仍要核对证据和版本。环境失败不能作为通过依据。
5. **确认维护者并联系**。运营人员在项目“联系与访谈”页确认公开资料所指的人是否实际维护者。两轮均通过后创建联系草稿。在外部渠道实际联系，再更新已发送、已回复或拒绝状态。工作台不发送消息。
6. **访谈**。维护者回复后，记录用户、投入、规划、Credits 需求、里程碑及访谈同意。工程师与创业者画像可同时选择，证据不足时选待判断。
7. **审批**。审批人在项目“赞助审批”页查看同项目访谈。批准时填写接收邮箱、金额（美分）、活动 slug、活动到期日、未来复盘日期、用途和账号依据。100 美分等于 1 美元；系统不能代替团队核实账号归属或活动设置。
8. **执行与到账**。另一位执行人在“赞助台账”核对计划。服务端开启写入且身份符合条件时，明确确认创建邀请。邀请不等于到账；在 Credits 后台完成实际领取，再点击“查询到账”。未知结果优先对账，不重复创建。
9. **复盘**。到账后出现复盘待办；历史已到账记录若缺少日期，运营或审核人员使用“补齐复盘安排”填写未来日期。记录额度使用、里程碑、证据和下一步。继续、调整或暂停时填写未来的“下一次复盘日期”；若已安排未来待办可以留空并复用。最后一条待办不能仅留下自由文本而没有下一次日期。调整/暂停结论不自动修改远端额度；结束关闭本地赞助周期并保留历史记录。

## 语言与仓库档案

用页头中文 / English 切换界面，偏好保存在当前浏览器。仓库档案同时保留原文和中文内容；README 阅读摘要单独标记，全文译文、未采集、待翻译、需更新及节选不会混为一类。用户填写的证据、代码和项目名称保持原样。列表可搜索当前中文简介，并组合方向、受众、阶段和入选状态筛选；进入详情查看当前下一步及历史记录。

## 失效与失败怎样处理

- 仓库版本变化、第一轮重审、审核过期、仓库归档或证据不完整，会使旧体验或旧结论失效。重新采集并按新版本审核，不能复制旧的通过结论。
- 表单保存失败时会展示服务端原因。相同内容的网络重试复用同一个请求标识；修改内容会建立新的操作。资金操作结果未知时关闭窗口并查询到账。
- 采集失败在“采集与运行”查看。限流会自动退避；终止失败的任务在核对原因后重试。
- 审核、访谈、体验和台账均保留历史；需要修正体验时创建新体验记录，不覆盖原始事实。
- 演示工作空间有醒目提示，只用于练习和验收，不能据其数字认为已联系作者或发放额度。

## 运行与交接

退出登录会撤销本应用会话，不会退出公司身份提供方的全局会话。服务重启会使内存会话失效。凭证不存入 localStorage/sessionStorage。

管理员使用 [部署手册](部署手册.md) 配置运行主机、HTTPS、密钥权限和备份；外部服务与真实业务验收使用 [上线验收清单](上线验收清单.md)。

## 团队待办与记录定位

概览中的每项待办可以点击，进入“团队待办”的对应分类；“查看并处理”定位到具体体验、复盘、采集记录或项目。待办权限随角色变化。Agent 执行中的任务独立显示，不重复计为可领取任务；作者未确认、拒绝联系或已有活跃联系时，项目进入待补齐条件。

已发生的作者回复可以在仓库版本变化后正常记录，保留实际沟通事实。继续访谈、联系或发放仍须重新满足有效审核与同意门槛。关闭联系后的项目进入观察状态，历史记录保留。

首页方案选择只解释支持条件，不提交申请。流程助手为本地规则导航，不调用模型或读取团队资料；真实 Agent 体验通过专用节点协议完成。
