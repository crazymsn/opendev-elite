# OpenDev Elite 部署与运维手册

Docker Compose 部署入口见 [Docker Compose 部署手册](DockerCompose部署.md)，包含初始化、凭证、HTTPS、备份和升级。以下保留 Windows / systemd 直接部署路径。项目显示名称为 OpenDev Elite，Python 分发名 `github-sponsorship-worker` 和既有数据目录保持兼容。

v0.6.1 新工作空间默认管理员为 OpenDev / 123456，成员由管理员在后台创建和授权，见 [账号注册与授权](账号注册与授权.md)。以下 Token 领取方式保留用于兼容和 Agent。v0.5.x 升级到 v0.6 将 schema 5 迁移为 schema 6；先备份并停止旧进程，再启动新版。已有账号与修改后的密码不会被默认账号初始化覆盖。

本项目可在一台机器上运行 API/UI 与采集 Worker。SQLite、凭据、日志放在本机专用目录，源码可以在 OneDrive，但运行数据不能放在 OneDrive、UNC 共享或链接目录。安装脚本不会注册计划任务、发送消息或发放真实 Credits。

## Windows 本机启动

在项目目录执行。使用已安装项目可选依赖的 Python/虚拟环境；不要为了启动切换到没有依赖的解释器。

```powershell
python -m pip install -e .
python -m worker.deployment setup
./scripts/start-local.ps1 -Python (Get-Command python).Source
```

默认目录为 `%LOCALAPPDATA%/github-sponsorship`。Codex/MSIX 的文件重定向可能将实际目录放在 `Local/Packages/.../LocalCache/Local`，**以 setup/start 返回的 root 为准**；脚本会解析最终文件路径，避免重复启动时混淆 PID 记录。

浏览器打开 `http://127.0.0.1:8765`。配置 `service.local.json` 保存 token 哈希，`credentials` 下分别保存六个身份的原始 token，只将各自文件交给对应成员：

| 文件 | 职责 |
| --- | --- |
| technical-reviewer.token | 技术审核、产品体验审核 |
| relationship-operator.token | 作者确认、联系记录、访谈 |
| funding-approver.token | 赞助决策 |
| credits-operator.token | Credits 操作身份 |
| experience-agent.token | Agent 领取、续租、提交体验 |
| quality-auditor.token | 审计查询 |

在 UI 登录页粘贴自己的 token。不要把 token 放在 URL、截图、源码、工单或报告中。Windows 初始化设置受保护的目录 DACL，仅当前 Windows 用户、SYSTEM 和管理员可以访问；Linux 使用目录 `0700`、凭据 `0600`。六个角色不共享密钥，Agent 不具备审核或财务权限。

重复 setup 不轮换密钥、不覆盖配置、不重建数据库；发现现有凭据与配置不一致时停止并保留文件。若进程在初始化中被强制结束而遗留 `.setup.lock`，先确认没有 setup 进程，再手工移除该专用锁文件后重试。

### 独立合成演示

```powershell
$reviewRoot = Join-Path $env:LOCALAPPDATA 'github-sponsorship-v03-review'
./scripts/start-local.ps1 -Root $reviewRoot -Python (Get-Command python).Source -Demo
```

只有显式 `-Demo` 才建立 `demo.db` 和 `demo.SYNTHETIC.json`；生产 `worker.db` 保持为空。演示 Worker 只更新本地合成报告，不查询 GitHub、不请求 Credits。示例中的“已联系”“已到账”均为合成数据，不能作为真实业务证据。

### 停止、重复启动与日志

```powershell
./scripts/stop-local.ps1
./scripts/stop-local.ps1 -Root $reviewRoot
```

两个角色均隐藏启动。Windows 虚拟环境可能各带一个 Python launcher 子进程，这是解释器机制；脚本会验证并管理对应实例。PID、创建时间、解释器、完整命令行、部署目录、角色和唯一实例标记都匹配才允许停止；不会对不明 PID 使用全树删除。重复启动保留已有角色，不建立第二个采集 Worker。启动还会核对 8765 监听进程归属并检查 `/healthz`，失败时撤回本次新建的进程，保留已有进程及全部数据。

每个角色的主日志为 `logs/serve.log`、`logs/run.log`，单文件上限 4 MiB，保留 3 个滚动副本。bootstrap 日志只记录启动阶段诊断，每次新启动替换，不含 token。`runtime/*.json` 是本机进程标识，不能复制到另一台机器使用。停止后可随时重启；强制停止时未完成的数据库任务按租约恢复。

## Linux 单机部署模板

`deploy/` 提供 systemd API/Worker 单元、可选备份 timer、环境文件和 nginx TLS 反向代理模板。模板**没有自动安装或启用**，先检查路径和主机策略。

以下约定源码位于 `/opt/github-sponsorship`，由管理员维护；运行数据为 `/var/lib/github-sponsorship`。使用现有主机上的 Python 3.11+、systemd，以及团队已有 TLS 入口。不需要额外数据库或消息队列。

```bash
sudo useradd --system --no-create-home --home-dir /nonexistent --shell /usr/sbin/nologin sponsorship
sudo install -d -m 0700 -o sponsorship -g sponsorship /var/lib/github-sponsorship
sudo install -d -m 0750 -o root -g sponsorship /etc/github-sponsorship
sudo python3 -m venv /opt/github-sponsorship/.venv
sudo /opt/github-sponsorship/.venv/bin/python -m pip install /opt/github-sponsorship
sudo -u sponsorship /opt/github-sponsorship/.venv/bin/python -m worker.deployment setup --root /var/lib/github-sponsorship
sudo install -m 0640 -o root -g sponsorship /opt/github-sponsorship/deploy/worker.env.example /etc/github-sponsorship/worker.env
```

已有用户时无需重复 `useradd`。环境文件由管理员编辑，填写 GitHub 凭据；不要把真实凭据粘贴到 shell 历史。若采用 OIDC，按认证文档安装可选依赖并配置，保留同一个虚拟环境。默认 API 绑定 `127.0.0.1:8765`；只有本机 TLS 代理接收外网流量。

```bash
sudo install -m 0644 deploy/sponsorship-api.service deploy/sponsorship-worker.service /etc/systemd/system/
sudo systemd-analyze verify /etc/systemd/system/sponsorship-api.service /etc/systemd/system/sponsorship-worker.service
sudo systemctl daemon-reload
sudo systemctl start sponsorship-api sponsorship-worker
sudo systemctl status sponsorship-api sponsorship-worker
```

需要开机启动时，由运维显式执行 `systemctl enable`；撤销用 `systemctl disable --now sponsorship-api sponsorship-worker`，数据库和配置仍保留。两个服务都以 `sponsorship` 低权限用户运行，默认无 Docker socket/宿主机额外权限；Agent 容器在专用执行环境运行，不把服务器财务凭据传入容器。

`deploy/nginx-tls.conf.example` 的 `REPLACE_HOST`、证书和私钥路径必须替换为团队已有入口；同时将 `service.local.json` 的 `public_origin` 设置为真实 HTTPS origin。模板在 nginx 的 `http` 上下文定义登录限速 zone，token/SSO 登录入口默认每 IP 每分钟 5 次、突发 5 次，按团队实际情况调整。先运行现有 nginx 的配置检查，再按主机运维流程启用。模板没有虚构域名，也不会申请证书。API 端口不要直接暴露公网。

Linux API 使用同一启动模块，将日志写入受保护目录并按 4 MiB × 4 份滚动；Worker 及启动诊断交给现有 journald，单元限制日志速率。由主机管理员确认 journald 的容量与保存周期。

## 远程 Agent 自动领取与执行

在拥有 Docker 和经审核镜像的专用 Agent 主机安装本项目。只复制 `experience-agent.token`，不要复制审核/财务 token 或服务器生产凭据。准备自己的 `agent.local.json`，固定完整镜像 digest，镜像内含待评估版本的离线源码与依赖。

```powershell
$agentState = Join-Path $env:LOCALAPPDATA 'sponsorship-agent-outbox'
sponsorship-worker agent-poll --server http://127.0.0.1:8765 `
  --token-file C:/private/experience-agent.token --out $agentState `
  --config C:/private/agent.local.json --max-tasks 1
```

示例 `C:/private` 需换成真实受保护路径。远程服务器必须使用 HTTPS；只有 loopback 允许 HTTP。默认只领取一个任务后退出；`--max-tasks` 可显式设为 1–100，不会常驻、注册调度或启动额外服务。输出目录不能位于源码仓库、OneDrive、UNC 共享或符号链接目录。

执行链为：领取当前合格体验 → 立即续租 → 后台心跳 → 同一个隔离执行核心运行固定 SHA/task digest → 核验实际输出 → 上传真实证据文件 → 提交结果。每个文件按 384 KiB 分块认证上传，绑定体验、run_id、路径、SHA-256 和字节大小；每个体验最多 100 文件、64 MiB。服务端保存完成的原始文件，审核者通过认证下载入口查看；未完成当前 run 证据上传时不能提交成功结果。HTTP Agent token 和 lease_token 不会传入 Docker 环境或挂载。心跳失败/租约过期会在执行轮询中取消客户端并请求删除该实例容器，随后阻止提交；不能继续运行到租约被别人接手。清理无法确认时停止整个消费批次，等待专用执行环境检查。

`outbox.json` 和每个运行目录保存任务、原始幂等键、结果及短期 lease_token，受操作系统私有目录权限保护；不得复制进仓库或公开报告。常见结果：

| 状态 | 后续处理 |
| --- | --- |
| submitted | 服务端 ACK 的体验 id 与结果匹配；这是体验证据提交，不是审核通过 |
| idle | 服务端明确返回 `task:null`，本次无任务 |
| claim_unknown / submit_unknown | 不再领取新任务；检查服务端后，用同一目录加 `--resume` 重放原始幂等键 |
| uploading / upload_unknown / preparing_artifacts | 保留原始文件和 outbox；`--resume` 在当前租约有效、文件哈希未变时继续同一块，不重新执行产品 |
| artifact_changed | 本地证据不再匹配已绑定清单；停止并人工核对，不能在原幂等键下换文件 |
| executing | 上次执行被中断，不能自动重跑；检查容器、租约、已有结果后处理 |
| lease_lost | 不提交旧结果；由审核人检查版本/租约状态并重新安排 |
| cleanup_required | 先确认并清理该运行对应容器，禁止直接继续消费 |

`--resume` 只重放已保存的领取、证据分块或结果请求，不会重新运行不明状态容器。上传进度与每块幂等键在发送前持久化；服务端 ACK 的体验/run/文件/块信息匹配后才前进，后台心跳维持到最终结果 ACK。错误 ACK、空 JSON、缺少 `task` 字段均不会伪装成成功或空队列。Docker 缺失/镜像或执行环境异常会记录真实失败并标为 `environment`，不会构造通过记录。成功产品体验仍需第二轮人工复核。

当前测试使用真实 API 业务层、mock HTTP/Docker，并实际验证了子进程超时和失租取消；真实 Docker 守护进程、镜像和远程网络须在实际 Agent 主机联调。

## 健康、备份与恢复

```powershell
python deploy/healthcheck.py --root $reviewRoot
# 生产默认目录：附加 --api 检查本机服务活性
python deploy/healthcheck.py --root (Join-Path $env:LOCALAPPDATA 'github-sponsorship') --api
python deploy/backup.py --root (Join-Path $env:LOCALAPPDATA 'github-sponsorship')
```

健康命令默认只查本地数据库。`--api` 仅访问固定 loopback 地址，禁止代理与重定向；若配置了 HTTPS `public_origin`，它只从可信本地配置读取 netloc 作为 Host，不会向该远程域名探测。Windows 启动探活同样处理，返回的浏览器 URL 使用配置的公开 origin。返回非零退出码表示数据库/队列异常或本机服务不可用。`/healthz` 只代表 API 活性，不证明远程凭据、Docker 镜像、完整检索覆盖或赞助到账。

备份使用 SQLite 在线备份 API，写入全新时间戳文件；不覆盖、不删除旧备份，不包含凭据。Linux 可手动运行 `deploy/backup.py`，也可经运维审核显式安装并启用 `sponsorship-backup.service/.timer`。应另按组织规范加密备份凭据配置，并设置存储配额与离线保留策略。

恢复时先停止 API 和 Worker；保留当前数据库作为故障证据，将经 `PRAGMA integrity_check` 验证的备份恢复到新部署目录，配回同一组身份配置和受保护凭据，再离线 doctor、启动和核对业务台账。不要直接复制正在写入的 SQLite 文件，也不要覆盖唯一一份故障数据库。

## 真实外部配置尚需提供

- GitHub：实际采集使用的 token 和配额策略；匿名仅能低速读取公开数据。
- Credits：真实 HTTPS API 地址、活动 slug、核实过的活动有效期与 PAT；默认关闭真实 Credits 写入。生产模式存在 `root/credits.local.json` 时启动器将其交给 API。配置验证完成后可显式将 `service.local.json` 的 `allow_credit_writes` 设为 `true` 并重启；未提供 Credits 配置时拒绝启用。演示模式始终关闭写入且不加载真实 Credits 配置。
- Agent：经审核、固定 digest 的执行镜像，离线源码及依赖，Docker 可用环境。
- 团队入口：真实域名、TLS 证书、网络访问策略；如使用 SSO，还需真实 OIDC 配置与依赖。

这些配置缺失不能用合成演示或健康绿灯替代。代码已提供初始化、启动、停止、备份和诊断能力；部署模板的 Linux 启动仍须在目标 Linux 主机验证。

## v0.4 安装升级补充

Windows 启动脚本现在用 `-I` 隔离导入，从 `-Python` 指向的解释器已安装包启动。先安装 wheel（或开发时安装 editable 包），再运行启动脚本。不要只复制源码而不安装。

```powershell
python -m pip wheel . --no-deps --wheel-dir artifacts/dist
python scripts/package-release.py --test-log artifacts/validation/tests-v04-final.txt
# 在专用运行环境安装对应 wheel，再用该环境启动。
./scripts/stop-local.ps1 -Root $productionRoot
& $runtimePython -m pip install --no-deps --force-reinstall artifacts/dist/github_sponsorship_worker-0.4.0-py3-none-any.whl
./scripts/start-local.ps1 -Root $productionRoot -Python $runtimePython
```

上面变量必须指向已有部署和运行解释器；升级前完成新备份并验证。当前 schema 仍为 4。Windows 端口采用独占监听；默认启动器固定 8765，不允许两个部署共用。并行浏览器验收使用单独 demo 配置、数据库和 `main.py serve --port 8874`，public_origin 也需匹配。

源码包按白名单生成，包含代码、测试、设计系统、文档和部署脚本，排除实际凭证、数据库、local 配置和运行 outbox。manifest 记录安装包/源码包 SHA-256 及完整测试日志摘要。不要把 `python -m worker.cli` 当作启动命令；使用已安装的 sponsorship-worker 命令、main.py 或部署脚本。
