> 版本：v0.8.0  
> 包名：`github-sponsorship-worker`  
> 适用对象：部署人员、研发、运营、审核、审批与审计成员  
> 配套文档：[README](../README.md) · [团队操作指南](团队操作指南.md) · [部署手册](部署手册.md) · [账号注册与授权](账号注册与授权.md) · [项目入选与排除标准](项目入选与排除标准.md)

## 1. 项目是什么

**OpenDev Elite** 是一套面向「GitHub 开源项目赞助」的证据驱动工作台。它把下面整条业务链串在同一套本地/自托管系统里：

1. **发现与采集**：按日期/Stars 等条件搜索或手工导入候选仓库，拉取公开元数据、提交、发布、议题与代码样本。  
2. **入选评估**：按五项质量门槛打分（需求 / 工程 / 维护 / 差异化 / 可评测性），总分与单项均须达标。  
3. **两轮人工审核**：第一轮技术复核 → 真实产品/Agent 体验 → 第二轮基于体验的复核。  
4. **联系与访谈**：确认真实维护者，记录外联与访谈画像（系统本身不代发消息）。  
5. **赞助审批与 Credits**：审批条款 → 另一人执行邀请 → 查询到账 → 复盘。  

核心原则：**证据优先、角色分离、服务端重算分数、不把 Stars/搜索命中当成通过依据**。默认运行时仅依赖 Python 标准库；OIDC SSO、真实 Credits 写入、远程 Agent 镜像为可选联调能力。

## 2. 工程结构一览

```
GitHub_Worker/
├── main.py                 # 跨平台 CLI 入口（调用 worker.cli）
├── pyproject.toml          # 包定义；脚本名 sponsorship-worker
├── compose.yaml / Dockerfile
├── .env.example            # Compose 可选环境变量模板
├── config/                 # 发现、GitHub 身份等示例配置
├── worker/                 # 主业务包（API、工作流、采集编排、账号、Credits…）
│   ├── cli.py              # 全部子命令
│   ├── service.py          # HTTP API / 浏览器工作台后端
│   ├── deployment.py       # 本机 setup / 进程托管
│   ├── pipeline.py         # 采集管线
│   ├── workflow.py         # 审核 / 访谈 / 赞助状态机
│   ├── criteria.py         # 入选评分规则
│   ├── accounts.py         # 账号与密码
│   ├── web/                # 前端静态资源（HTML/JS/CSS）
│   └── resources/          # 策略 JSON（如 selection-policy）
├── src/py/                 # 原爬虫复用层（fetcher / userinfo 等）
├── scripts/
│   ├── start-local.ps1     # Windows 一键启动 serve + run
│   ├── stop-local.ps1      # 停止本机进程
│   └── local-runtime.ps1   # 启动脚本公共逻辑
├── deploy/                 # systemd / nginx 模板（需人工启用）
├── docs/                   # 规格、交付说明、操作手册
├── tests/                  # 单元与集成测试
└── artifacts/              # 报告、发布校验产物（勿当运行库）
```

| 层次 | 职责 |
| --- | --- |
| `worker/` | 业务真相源：库表、权限、评分、审核流、HTTP、部署 |
| `src/py/` | GitHub 公开数据抓取与用户画像，被 Pipeline 调用 |
| `worker/web/` | 团队浏览器工作台 |
| `scripts/*.ps1` | Windows 本机双进程（API `serve` + 采集 `run`）托管 |
| Compose | `init` + `api` + `worker` + `gateway`，默认宿主机端口 8780 |

数据默认落在**本机专用目录**（Windows：`%LOCALAPPDATA%\…`），**不要**把运行中的 SQLite 放在 OneDrive / UNC / 网盘同步路径上。源码可以在 OneDrive，运行态不行。

## 3. 运行时架构

```
浏览器 ──► HTTP(S) API :8765（或 Compose 网关 :8780）
                │
                ├─ SQLite（项目、证据、账号、台账、审计）
                ├─ credentials/（兼容 Token / Agent Token 文件）
                └─ 会话 Cookie（密码登录；不写 localStorage）

采集 Worker（独立进程）
  schedule / import → 队列 → work → fetcher/userinfo → 写回 DB
```

本机启动时通常有两个隐藏进程：

| 进程 kind | 作用 |
| --- | --- |
| `serve` | 提供工作台与 JSON API，监听 `127.0.0.1:8765` |
| `run` | 消费采集队列，拉取 GitHub 公开资料 |

健康检查：`GET /healthz` 返回 `{"ok": true}`。

## 5. 如何启动（三种方式）

### 5.1 Windows 本机（推荐日常开发 / 本机已验证路径）

在 `GitHub_Worker` 目录：

```powershell
# 1. 安装包（可编辑模式）
python -m pip install -e .

# 2. 初始化运行根目录（生产示例目录名）
$appRoot = Join-Path $env:LOCALAPPDATA 'github-sponsorship-production'
python main.py setup-local --root $appRoot

# 3. 启动 API + 采集进程
./scripts/start-local.ps1 -Root $appRoot -Python (Get-Command python).Source
```

成功时脚本输出 JSON，例如：

```json
{
  "status": "running",
  "url": "http://127.0.0.1:8765",
  "root": "C:\\Users\\…\\AppData\\Local\\github-sponsorship-production",
  "synthetic_demo": false
}
```

浏览器打开：

- 登录页：http://127.0.0.1:8765/#team-login  
- 默认管理员：`OpenDev` / `123456`（仅空库首次初始化写入；改密后重启不会覆盖）

停止：

```powershell
./scripts/stop-local.ps1 -Root $appRoot
```

说明：

- 重复执行 `start-local.ps1` **不会**再拉起第二套 Worker；会复用已健康的进程。  
- 启动会检查 8765 端口归属与 `/healthz`；失败则回滚本次新建进程，保留已有数据。  
- 日志：`$appRoot\logs\serve.log`、`run.log`（约 4 MiB 滚动）。  
- 若未指定 `-Root`，默认根目录为 `%LOCALAPPDATA%\github-sponsorship`。

### 5.2 Docker Compose

```sh
# 可选：复制环境变量
cp .env.example .env

docker compose up -d
docker compose ps -a
```

默认访问：http://127.0.0.1:8780  
详细凭证、HTTPS、备份与升级见 [DockerCompose部署.md](DockerCompose部署.md)。

### 5.3 Linux systemd（模板，需人工启用）

见 [部署手册.md](部署手册.md)：源码建议 `/opt/github-sponsorship`，数据 `/var/lib/github-sponsorship`，单元文件在 `deploy/`，默认仍绑定本机 `127.0.0.1:8765`，由 nginx TLS 反代对外。

### 5.4 独立演示环境（禁止当真业务）

```powershell
$reviewRoot = Join-Path $env:LOCALAPPDATA 'github-sponsorship-v03-review'
./scripts/start-local.ps1 -Root $reviewRoot -Python (Get-Command python).Source -Demo
```

只有显式 `-Demo` 才会使用合成库；界面有演示提示。「已联系 / 已到账」等为假数据，不能用于验收真实发放。

## 6. 启动后目录里有什么

以 `setup-local --root <ROOT>` 为例：

| 路径 | 含义 |
| --- | --- |
| `<ROOT>/worker.db` | 主 SQLite 业务库 |
| `<ROOT>/service.local.json` | 服务配置（含 token 哈希等） |
| `<ROOT>/discovery.local.json` | 本地发现配置 |
| `<ROOT>/credentials/*.token` | 六类兼容角色原始 Token（按人分发） |
| `<ROOT>/logs/` | serve / run 日志 |
| `<ROOT>/runtime/*.json` | 本机 PID 记录（不可拷到别的机器） |

`setup-local` 返回的 JSON 还会标明：是否已装 Agent/Credits 配置、是否检测到 `GITHUB_TOKEN` 等。

## 7. 登录与成员

1. 打开登录页，用 **OpenDev / 123456** 进入（新空库）。  
2. 进入 **成员与权限 → 新增成员**，填写账号、显示名、初始密码（≥15 字符）、角色。  
3. 日常成员用账号密码登录；无需再分发 Token。  
4. 「其他登录方式」折叠区仍支持旧 Token；Agent 继续用专用 Token。  
5. 配置 OIDC 后可走公司 SSO（见 [SSO接入说明.md](SSO接入说明.md)）。

角色与职责（可组合，但**审批人与 Credits 执行人必须不同 actor**）：

| 角色示例 | 主要工作 |
| --- | --- |
| relationship-operator | 导入、分配、维护者确认、联系、访谈 |
| technical-reviewer | 技术复核、体验设计/人类体验、第二轮审核 |
| funding-approver | 赞助审批与条款 |
| credits-operator | 核对计划、创建邀请、查询到账 |
| quality-auditor | 流程与操作审计 |
| experience-agent | 仅 Agent API（自动领任务、回传证据） |

密码重置（本机有 DB 文件权限时）：

```powershell
python -I -m worker.accounts reset-password --db "<ROOT>/worker.db" --username OpenDev
```

## 8. 业务主流程（工作台）

完整细则见 [团队操作指南.md](团队操作指南.md)。摘要：

```
导入候选 → 入选五项评分 → 第一轮技术复核
    → 人类/Agent 真实体验 → 第二轮复核
    → 确认维护者并外联 → 访谈
    → 审批（美分金额、活动、复盘日）
    → 另一人执行 Credits 邀请 → 查询到账 → 复盘
```

### 8.1 入选质量门槛（v0.8）

| 维度 | 权重 |
| --- | --- |
| 真实需求与任务价值 | 20% |
| 工程成熟度 | 25% |
| 维护连续性与响应 | 20% |
| 差异化与新增贡献 | 20% |
| 可评测性与使用边界 | 15% |

每项 0–4 分；**总分 ≥ 80 且每项 ≥ 3**；维护须提供过去一年天内两个不同日期 + 两个对应来源。服务端重算分数，不可客户端绕过。公式：

`总分 = Σ(该项评分 ÷ 4 × 该项权重)`

支持范围与暂缓/排除条款见 [项目入选与排除标准.md](项目入选与排除标准.md)。

### 8.2 工作台常用区域

- **概览 / 团队待办**：按角色看可执行项，点进具体项目或记录  
- **候选项目**：导入、筛选、入选评估、审核入口  
- **仓库档案**：中英简介、README 摘要/译文、技术证据（提交/发布/议题/代码预览）  
- **产品体验**：人类体验记录；Agent 体验另走专用协议  
- **联系与访谈 / 赞助审批 / 赞助台账**  
- **采集与运行**：队列、限流、失败重试  
- **成员与权限 / 账号设置**  
- 页头可切换 **中文 / English**（偏好存浏览器；证据原文不改写）

## 9. CLI 命令速查

在 `GitHub_Worker` 目录（或已安装的 `sponsorship-worker`）：

```powershell
python main.py --help
```

| 命令 | 用途 |
| --- | --- |
| `init` | 初始化数据库 |
| `setup-local [--root] [--demo]` | 生成本机部署目录与配置 |
| `serve --config …` | 仅启动 API（手工） |
| `schedule --config … [--start] [--end]` | 按发现配置写入搜索任务（不注册系统定时器） |
| `import owner/repo …` | 导入一个或多个仓库 |
| `import-csv path.csv` | 从 CSV 导入地址并重新采集 |
| `work [--max-jobs N]` | 有界执行队列任务 |
| `retry-job ID` | 显式重试失败任务 |
| `status` | 查看队列/运行状态 |
| `report --out …` | 生成报告 |
| `project ID` | 导出单项目视图 |
| `doctor` | 健康/配置诊断 |
| `backup DEST` | 备份 |
| `acceptance` | 上线验收相关检查 |
| `agent-poll / agent-run / agent-export` | Agent 执行侧 |
| `credits-plan / credits-submit / credits-reconcile` | Credits 侧（需配置） |
| `translations-export / translations-import` | 档案译文批处理 |
| `auth-key` | 生成兼容角色密钥文件 |

典型采集循环：

```powershell
python main.py schedule --config config/discovery.json --start 2026-06-01 --end 2026-09-07
python main.py work --max-jobs 20
python main.py status
```

公开仓库可匿名读；批量请设置环境变量 `GITHUB_TOKEN` 或按 [GitHub采集身份配置.md](GitHub采集身份配置.md) 复用 `gh` 登录。

## 10. 配置要点

| 配置 | 说明 |
| --- | --- |
| `GITHUB_TOKEN` / 采集身份 JSON | 提高搜索与 API 限额 |
| `service.local.json` | 监听、公钥 origin、token 哈希等 |
| `.env`（Compose） | `OPENDEV_PORT`、`OPENDEV_PUBLIC_ORIGIN`、镜像标签、Credits PAT |
| Credits / Agent 本地 JSON | 未安装时相关写入与 Agent 联调不可用；工作台其他流程仍可跑 |
| OIDC | 可选依赖 + SSO 文档 |

金额约定：台账以**美分**计，`100` = `$1`。系统不代替核实收款账号归属或活动后台设置。

## 11. 安全与运维注意

- 默认只监听本机回环；对外必须经 HTTPS 反代，并设置正确的 `public_origin`。  
- 密码：PBKDF2-HMAC-SHA256；Cookie：HttpOnly / SameSite；写操作校验 Origin + CSRF。  
- 兼容 Token 按角色分文件保管，勿进仓库、截图、工单。  
- Agent 节点只部署 `experience-agent` Token，不要带审批/财务密钥。  
- 备份：停止写入或按手册冷备 `worker.db` 与配置；升级前先备份。  
- 仓库版本变化、重审、归档会使旧体验/旧结论失效，需按新版本重走流程。  
- 资金类结果「未知」时：先对账，勿盲目重复创建邀请。

## 13. 常见问题

**Q：端口被占用 / 启动健康检查失败？**  
查看 `<ROOT>\logs\serve.bootstrap.err.log` 与 `serve.log`；确认没有其他程序占用 8765，或用 `stop-local.ps1` 清掉本部署进程后重试。

**Q：导入了项目但工作台一直没数据？**  
确认 `run` 进程在跑；在「采集与运行」看队列；限流会退避退出，可稍后 `work` 或等本机 run 循环继续。

**Q：Docker 命令找不到？**  
可改用本文 §5.1 Windows 本机路径，无需 Docker。

**Q：能否把数据库放在桌面/OneDrive 工程目录？**  
不建议。用 `LOCALAPPDATA` 下独立 root；源码同步与运行态分离。

**Q：演示数据和生产数据会混吗？**  
不会，前提是演示使用独立 `-Root` 且加 `-Demo`。不要对生产 root 加 `-Demo`。

**Q：忘记管理员密码？**  
用 §7 的 `worker.accounts reset-password`（需本机文件权限），不要指望公开找回。
