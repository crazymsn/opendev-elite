# v0.4 逻辑改进与兼容说明

## 业务缺陷与修复

| 原问题 | 现在的行为 | 回归证据 |
| --- | --- | --- |
| 历史已结束赞助遮蔽新的批准 | 按当前 grant/decision/contact 事实计算阶段；新待发放周期显示 approved | test_workflow_v04：closed_historical_grant、pending_approval |
| 仓库变更后实际作者回复无法记录 | 允许记录入站 replied；继续访谈、联系、发放仍需当前有效审核和作者同意 | inbound_reply_after_commit_change / expiration |
| 联系待办包含未确认或拒绝联系作者 | ready 队列必须有已确认、可联系且无其他活跃联系的维护者；不满足进入 blocked_contacts | ready_queue、author_already_contacted |
| 联系门槛与执行器快照完整性/时效不一致 | workflow.evidence_gate 由工作流、报告和执行器复用；缺失、不完整、过期、未来时间均不能前进 | incomplete_snapshot、future_dated、runner_and_report |
| 有效 Agent 租约仍计入待领取 | pending/running/stale 分组；租约过期后才回到 pending | active_agent_lease |
| 最后一次复盘继续后没有下一待办 | 要求下一次未来日期，或复用已有未来待办；结束取消剩余任务 | final_followup、explicit_followup_date、bad_followup_date |

阶段保留业务事实，不表示过去的审核仍然有效。已有审批或已联系项目仍可能需要重新复核证据；任何推进动作在服务端重新检查。再次产品评审不会自动撤销已拒绝的赞助决定。

## API 与 UI 契约

- 新增按角色分类的 `/api/inbox`。分页、计数和条目共用一个只读 SQLite 快照；未知、空或重复参数明确拒绝。
- 新增 `/api/records/{table}/{id}`，沿用该表权限。待办连接到具体记录，避免仅跳转到第一页列表。
- `result.next_review_at` 在复盘继续/调整/暂停且无未来待办时必填。旧客户端如已安排未来复盘可继续省略；最后一条任务必须升级请求。空字符串不是合法日期，应省略或填写未来 ISO 日期。
- 联系状态表单移除未定义函数调用；已关闭/拒绝的记录不再显示可用更新按钮。
- 人类体验成功自动对应 failure_kind=none；审批金额等字段仅在 approve 时要求；待定画像与明确画像互斥，工程师与创业者可并存。

## 会话与运行隔离

审核数据、Credits 计划和提交响应绑定当前身份、页面和操作代次；退出、切页或关闭后，旧响应不能再打开对话框或覆盖新表单。过期会话的退出 401 会清除工作台内容和提示。

Windows HTTP 监听采用 SO_EXCLUSIVEADDRUSE，禁用端口复用，防止演示实例与正式实例争用同一监听。固定端口的启动脚本遇到端口占用应失败，不能共用；并行验收使用 CLI 的显式 `--port`。

Windows 启动脚本使用 Python `-I` 隔离导入，从所选解释器已安装的包启动。升级前需要将新 wheel 安装到该运行环境；开发时可安装 editable 包。本机生产库与演示库完全独立。

本次 schema 保持 4，不删除或重写历史业务记录。公开首页、辅助问答与方案预览不访问私有项目数据，不调用外部聊天模型，不触发联系或赞助。
