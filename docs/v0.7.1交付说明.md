## 发现与工程证据

1. 新发现任务默认 `fork_mode: include`，不再在采集阶段统一漏掉 Fork。项目仍须审查相对上游的实际贡献。GitHub 的 `fork:true` 同时包含 Fork 和非 Fork，官方定义见 [仓库检索文档](https://docs.github.com/en/search-github/searching-on-github/searching-for-repositories)。
2. 配置允许全局和单个查询选择 `include / exclude / only`；查询中明确的 Fork 限定符优先。引号内的检索文本原样保留；多个明确限定符拒绝执行。实际范围进入任务标识和采集覆盖记录。
3. 旧排队任务没有范围字段时继续原来的排除 Fork 范围，避免正在翻页的查询中途改变含义。新范围从新任务开始；已有项目按稳定 ID 保留。
4. 新增多语言采样，包括 Julia、C/C++、C#、Java、TSX、Vue 等。每仓最多三份实现、一份测试、一份依赖声明、一份 CI 配置；每文件上限 80,000 字节。优先实际实现，跳过空文件、常见生成代码和第三方目录，并保留未采原因及目录树截断提示。
5. 每个样本记录角色、路径、大小和 blob SHA，通过同一提交 SHA 读取。路径启发式不能保证命中完整核心链路；需要负责人补读未覆盖模块和大文件。采样不执行第三方代码，也不生成评审或人才分数。

原 GitHub Worker 的 `src.py.fetcher`、`userinfo` 继续复用。现有本地发现配置不必重写，缺省范围由新任务逻辑处理；显式配置范围的查询按自身设置执行。
