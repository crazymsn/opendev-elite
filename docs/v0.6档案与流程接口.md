# v0.6 档案、入选与后续复盘接口

本文对应已交付的 v0.6.0、SQLite schema 6；本机工作台已完成升级。原始业务内容、项目名、代码和用户证据保持原样；界面语言由浏览器的中文 / English 选择控制。

## 入选与项目列表

`GET /api/criteria` 返回当前标准版本、双语方向、分轮标准及共同原则。检索结果只是候选。入选需记录方向适配、持续维护、当前 SHA、来源、理由及责任人；全球个人、小团队、早期和零 Stars 项目均可进入评估。不确定时暂缓，不凭检索关键词自动通过。

`GET /api/projects` 支持：

| 参数 | 含义 |
| --- | --- |
| `q` | 最多 200 字符；搜索仓库名、原简介及当前有效的中文/英文简介 |
| `selection` | `unassessed` / `include` / `hold` / `exclude` / `stale` |
| `category` | 最近一次评估的方向；与 `selection=include` 组合才能要求当前有效入选 |
| `audience` | `unknown` / `human` / `agent` / `both` |
| `stage` | 工作流阶段，完整枚举见 `/openapi.json` |
| `sort` | `updated` / `name` / `stars`；Stars 排序不改变入选门槛 |
| `page`, `page_size` | 分页，上限分别为 100000、200 |

未知参数、重复参数、无效枚举被拒绝。列表总数与当前页共享数据库读取快照。

`GET /api/projects/{id}` 返回当前评估、最近快照、最近 100 条审核、双语档案和 `readiness`。完整评估/审核历史使用 `GET /api/records/qualifications?project_id={id}`、`GET /api/records/reviews?project_id={id}` 分页读取。两者供有工作台阅读权限的人类角色访问，Agent 不具有后台读取权限。联系人、访谈、财务和复盘保留各自权限范围。

CLI 使用相同判断逻辑：

```sh
python main.py --db path/to/worker.db project 123 --out artifacts/project-123.json
```

输出含 `qualification`、`qualifications` 历史、`dossier` 和 `readiness`。CLI 直接持有数据库文件权限，适用于部署者；Web/API 则额外按当前账号过滤记录链接和操作权限。

## 当前下一步

`readiness` 不写入任何审核、联系或发放记录。新评审/新发放继续受当前资格、SHA、证据时效、两轮审核及作者意愿约束；`allowed` 是业务门槛提示，前端还需结合 `/api/ui-config` 的角色能力。打开表单并不等于有权通过审核，最终由服务端校验。

| 当前事实 | 下一步 |
| --- | --- |
| 未分配 / 缺少资料 / 未评估 | 分配 / 刷新采集 / 入选评估 |
| 资格有效，技术或体验未通过 | 技术复核 / 实际体验与第二轮复核 |
| 联系草稿 / 已联系 / 已回复 | 核对草稿 / 等待回复 / 访谈 |
| 作者拒绝 / 联系结束 | 停止建联 / 复核后续安排 |
| 赞助暂缓 / 拒绝 | 补充依据 / 保留不予赞助结论 |
| 待发放且批准过期 | 重新核对决定，不提示直接发放 |
| 提交中 / 结果不明 | 先对账，避免重复创建邀请 |
| 等待领取 | 等待领取并核实到账 |
| 已到账 | 按日期复盘；即使仓库后来归档或证据过期仍需跟进 |
| 已到账但无待复盘记录 | 补齐复盘安排 |
| 本轮已结束 / 已取消 | 明确显示结束或取消；新的批准以新周期处理 |

`next_record` 仅指向当前角色有权读取的记录；无复盘阅读权限不会得到 `next_review_at`。已有财务义务优先于新评审的准备工作，不因后来的 SHA 变化而隐藏。

`POST /api/actions/followup-schedule` 由运营或审核角色执行，JSON 为 `{"grant_id":"...","due_at":"YYYY-MM-DD"}`。赞助须已到账，日期须在未来。同笔赞助同一天的待办会复用；已完成日期不能覆盖。该操作只新增复盘待办，不发放 Credits。批准赞助至少安排一次未来复盘；继续、调整或暂停复盘后必须有明确下一日期，结束会关闭本轮并取消剩余待办。

## 中文档案的更新流程

简介、README 全文译文、README 阅读摘要分别保存，字段为 `description`、`readme`、`readme_summary`，目标语言为 `zh-CN` 或 `en`。阅读摘要不是全文译文。采集超过 40000 字符的 README 会保留节选并在界面注明，摘要与译文仅基于已保存的源文。

```sh
python main.py --db path/to/worker.db translations-export --field description --language zh-CN --out artifacts/description-work.json
python main.py --db path/to/worker.db translations-export --field readme_summary --language zh-CN --out artifacts/readme-summary-work.json
python main.py --db path/to/worker.db translations-import --file artifacts/description-ready.json --actor translator-name
```

保留导出项中的 `project_id`、字段、语言与 `source_sha256`，填写 `content` 和 `method`（`human`、`assistant` 或 `provider`）。导入逐项校验源文，并在同一事务内提交；任一项原文改变则整批回滚。重新导出并核对变化后再导入，不更改摘要来强行匹配旧译文。相同内容重复导入不会追加重复译文；修订内容以新记录留存。源文改变后旧译文显示为需更新，且不再参与当前简介搜索。

网页译文编辑采用相同校验。失效会话会关闭编辑器并清除原文与未保存草稿。原文缺失时没有“编辑译文”入口。

2026-09-07 本机升级时再次核对全部源文，已向正式数据库导入 145 条中文简介和 15 份中文 README 阅读摘要，全部来源校验为 current。另有 130 个项目尚无采集的 README。后续采集新增或改变源文时按上述流程补译，不把阅读摘要标为全文译文，也不把译文当作产品体验或审核通过。数据和验证证据见 [v0.6 交付说明](v0.6交付说明.md)。


## v0.6.1 / 标准 v2 的入选证据契约

`qualify` 请求仍保存到 schema 6 的历史表，新增内容在 `evidence` 中；无需数据库 schema 升级。`GET /api/criteria` 新增 `scope_paths`、`prerequisites`、`maintenance_guidance`、`hold_reasons`、`exclusion_reasons`、`priorities`、`evidence_rules`、`maintenance_kinds` 和 `assessment_fields`，全部提供中英文本。新方向 ID 为 `agent-applications`，原方向保持兼容。

| evidence 字段 | 校验 |
| --- | --- |
| `scope`, `maintenance`, `sources` | 仍为基础证据；sources 现在必须为非空字符串列表 |
| `reason_code` | 入选用 `none`；暂缓/排除分别使用目录中的对应原因 ID，不能混用 |
| `use_case`, `delivery`, `access_risk` | 入选时均须非空文本；暂缓时允许未知，不能为填表编造事实 |
| `maintenance_kind` | `unknown` / `commit` / `release` / `response` / `mixed` / `timestamp_only`；active 只接受中间四种实质信号 |
| `maintenance_date` | active 时必填 YYYY-MM-DD，为引用的维护事实日期，不得在未来；没有自动按天数淘汰的门槛 |

`outside_scope` 要求 `scope_fit=no`；`abandoned` 要求 `maintenance=inactive`。`no_real_value` 还要求当前 SHA 的第二轮拒绝结论及其关联的已完成产品体验，环境失败不足以排除。表单中的理由应说明证据和重新评估条件。

标准版本已改为 `sop-2026-09-v2`。旧版请求若缺少新增必需证据将收到验证错误，需更新调用方，不能依赖静默补齐。旧版评估历史保留并标记需重评；不自动重新通过已有项目。完整条款见 [项目入选与排除标准](项目入选与排除标准.md)。
