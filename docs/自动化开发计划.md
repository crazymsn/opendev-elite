# OpenDev Elite：当前开发规格

更新：2026-09-08。当前源码 v0.8.0，[账号登录与授权](账号注册与授权.md) 使用默认管理员、后台成员创建、密码登录和权限管理；继续支持 [Docker Compose 部署](DockerCompose部署.md)。当前优化与验收见 [v0.6 工作台规格](v0.6工作台优化规格.md)，档案和流程接口见 [v0.6 接口说明](v0.6档案与流程接口.md)。历史规划见 [架构归档](archive/自动化开发计划-v0.1-v0.3.md)，不能作为当前完成状态的依据。

## 产品目标

在全球发现仍在维护的 AI 开发者工具和 Agent 基础设施，通过代码复核、真实体验及作者访谈决定支持。覆盖个人、小团队、早期项目，以及 Agent Infra、AI Coding、RAG、模型路由、推理和应用产品。Stars 和地域不决定录取。

成功标准是每次联系与赞助都有有效证据、明确责任人和可追溯决定。采集数量、自动评分、模拟体验以及邀请创建均不能替代审核通过或到账。

## SOP 契约

| 步骤 | 输入与门槛 | 完成证据 / 出口 | 责任 |
| --- | --- | --- | --- |
| 发现项目 | 检索配置、人工地址或历史 CSV | 稳定仓库 ID、来源与采集状态，部分覆盖单独报告 | 采集 / 运营 |
| 项目和作者资料 | GitHub 公开数据 | Commit 快照、作者关系、采样范围；维护者需确认 | 采集 / 运营 |
| 入选评估 | 候选资料、当前 SHA、方向与维护来源 | 五项评分总分 ≥80、每项 ≥3/4，逐项证据和一年内两个维护日期；明确入选/暂缓/排除，不按地域、Stars 或团队规模硬淘汰 | 运营 / 技术审核人 |
| 第一轮技术复核 | 当前有效入选、完整快照、负责人、目标用户 | 工程结构与代码质量、Commit 与持续维护、文档与规范的理由和证据 | 技术审核人 |
| 第二轮产品体验 | 有效第一轮通过、事先定义的场景和成功条件 | 人用由团队体验，Agent 用由自有 Agent 执行并签收，混合产品两类都需证据；判断真实问题、使用表现、差异化与潜力 | 体验团队 / Agent / 审核人 |
| 联系 | 当前且未过期的两轮通过、确认维护者 | 草稿及实际触达/回复记录；拒绝后禁止继续建立联系 | 运营 |
| 第三轮访谈 | 作者已回复且愿意沟通 | 结构化纪要、自述、问题、机会与下一步 | 运营 / 计划负责人 |
| 决策与画像 | 有效评审和访谈、接收身份、额度、活动期限及复盘日期 | 批准/暂缓/拒绝；工程师/创业者/兼具/待定依据事实 | 审批人 |
| Credits | 已批准决策及服务配置 | 邀请仅为待领取；核对账户、激活和额度后才算到账 | 独立发放人 |
| 后续复盘 | 到账记录、到期任务、里程碑及可取得用量 | 继续/调整/暂停/结束；续额度需新决策 | 运营 / 审批人 |

## 不可破坏的业务约束

1. SHA、评审轮次、有效期和目标用户必须一致；重新审核或版本变化不能沿用过期结论推进联系与赞助。
2. 体验结果不可覆盖。Agent 结果绑定身份、租约、任务摘要及 run，产物验证真实字节大小与 SHA-256。
3. UI 提示只用于导航，服务端再次验证门槛和角色；审批人与发放人分离。
4. Credits 未知结果先核对，不能自动重发；额度总值不能当作增量充值。
5. 演示、真实数据和凭据分离；公开落地页不得读取真实候选、作者或审批数据。
6. 建联模块记录实际沟通，不自动发送；多渠道记录不能宣传成外部渠道已同步。

## 当前实现地图

| 模块 | 实现 | 约束 |
| --- | --- | --- |
| 采集 | 本地 src/py/fetcher.py、userinfo.py 进入 worker 正式调用链 | GitHub 只读、分页、限流退避、搜索拆分、稳定 ID 去重 |
| 存储 | SQLite schema 6、事务、入选评估与档案译文历史 | DB 与 outbox 位于本机专用目录，不在同步盘运行 |
| 工作流 | CLI、HTTP API、浏览器共用业务动作 | 人工判断签署，状态和证据可追溯 |
| Web | 同源静态页面、角色功能、HttpOnly 会话、CSRF | 不持久化浏览器凭证，不使用外部 CDN |
| 身份 | 默认管理员、后台创建成员、独立 Token、可选 OIDC | 公开注册关闭，账号密码和权限持久化；真实 IdP 待配置 |
| Agent | 领取、续租、执行、产物上传和幂等恢复 | digest 固定、资源上限、失租取消；真实镜像待配置 |
| Credits | openai-next-credits PAT 适配与核对 | 默认禁写；真实活动、PAT 和领取账户待配置 |
| 运维 | 安装包、启动/停止、健康、备份、部署模板 | 本机运行已验证；云端和开机托管单独验收 |

原爬虫整合详见 [整合说明](原爬虫整合说明.md)。Credits 契约详见 [接入说明](Credits接入说明.md)，未经核对不得臆造额度、活动或邮件接口。

## 开发和发布顺序

1. 先更新规格、边界与验收条件，区分当前实现和历史设想。
2. 独立审计 SOP 门槛、待办资格及接口，再实施逻辑改进和边界回归测试。
3. 完成页面结构、交互、状态、移动端和无障碍；写入验证只在独立演示库执行。
4. 运行完整测试、真实浏览器及安装包验证，逐项记录证据后升级本机运行包。
5. 保留上一版本与备份。外部联调缺口如实保留，不用演示代替真实验收。

## 0.7.1 入选标准执行与采集

默认包含 Fork 的发现，保持历史分页查询原范围；工程采样扩展多语言，分为实现、测试、依赖与 CI，绑定同一版本。三份真实候选静态预审用于准备负责人复核，不生成正式通过结论。见 [交付说明](v0.7.1交付说明.md)与 [技术复核准备](真实候选技术复核准备-20260908.md)。

## 0.7.2 技术证据阅读

将已采集的代码、提交、发布与议题呈现为负责人可阅读的复核材料，明确版本、采样局限和缺项。见 [规格](v0.7.2技术证据规格.md)。不改变正式评审与真实体验要求。

## 0.7.3 采集身份接入

本地部署可显式复用已登录的 GitHub CLI，避免未接入身份而长时间按匿名配额采集；不保存令牌到项目或配置。环境变量和 Secret 文件继续支持。见 [配置说明](GitHub采集身份配置.md)。

## 0.7.4 团队身份与实际闭环核查

上线身份检查纳入后台创建的活跃成员，合并兼容 Token，保留独立分工与 Agent 隔离，不读取密码哈希或输出成员资料。实际业务缺项与恢复条件见 [当前验收与交接](核心SOP当前验收与交接.md)。
