# 开发者档案与前期待办接口 · 0.7.0

保持 schema 6 和标准 sop-2026-09-v2。所有新增查询只读，不生成入选、维护者确认、访谈或赞助判断。认证与 OpenAPI 沿用现有服务。

## 开发者与团队

`GET /api/developers`：允许所有人类工作台角色，禁止匿名及专用 Agent 身份。参数 page（1..100000）、page_size（1..200，默认 15）、q（最多 200 字符）、kind（User/Organization）、relationship（candidate/confirmed）。未知/重复参数拒绝；分页空值拒绝，空筛选表示不限；q 对账号、公开姓名、关联仓库作字面匹配。

按 GitHub 稳定 ID 聚合，不靠同名/邮箱猜测同一人。账号可能在不同项目分别拥有待确认和已确认关系，所以两个关系筛选可以重叠。列表返回公开字段及关联项目/确认关系数量；不返回邮箱、原始 profile、拒绝联系状态或私有业务记录计数。公开简介和机构属于账号自述。

`GET /api/developers/{id}`：返回 entity、分页 projects、history_kinds。projects 沿用当前入选评估与翻译指纹判断，并标出 role/confirmed。联系权限用户可读 contact_preference；访谈权限用户可读 latest_interview（原始 ID、项目、画像、责任人和时间）。最近访谈描述的是当时的判断，不覆盖旧记录，也不声称永久身份或能力。

`GET /api/projects?maintainer_id={id}`：复用项目搜索与筛选，限定某一 GitHub 实体的关联仓库。

`GET /api/developers/{id}/records/{table}`：分页原始记录引用，table 仅 contacts/interviews/grants/followups。权限与原表一致，未授权角色连计数也不可读。grants/followups 通过对应决定→访谈→联系→维护者关联，不能把同项目其他人的记录归给此人。

| 记录 | 可读角色（管理员全部可读） |
| --- | --- |
| contacts | operator |
| interviews | operator、approver |
| grants | approver、disburser、auditor |
| followups | operator、reviewer、auditor |

历史列表提供出处、状态、日期、责任人或访谈画像，敏感正文继续通过既有 `/api/records/{table}/{id}` 授权读取。界面入口 `#developers`；详情 `#developers/{id}/{table}`；原始访谈深链 `#interviews/{id}`。

## 前期团队待办

`/api/inbox`、`/api/status`、`/api/ui-config` 和报告新增四类。原有默认 API 类别 pending_experiences 保持兼容；界面从当前角色可见类别选择。

| kind | 权限 | 判定/目的地 |
| --- | --- | --- |
| unassigned_projects | operator、reviewer | readiness.next_step=assign，项目详情 |
| awaiting_collection | operator | refresh-project，项目详情刷新证据 |
| pending_selection | operator、reviewer | qualify，项目入选评估页 |
| pending_technical_reviews | reviewer | review-one，两轮审核页 |

每个项目最多进入一个前期类别，依赖共用 readiness，不能只按 stage 认定已过门槛。暂缓、拒绝、结束、归档或禁用项目不自动重新分配；既有对账、领取和到账复盘义务优先。列表、计数和项目绑定处于同一读快照，读取不会修改业务状态。

## 访谈输入

用户需求、投入、路线图、Credits 需求、里程碑须为非空文本证据（或非空文本列表）。拒绝布尔、数字、空白及结构对象。profile 为非空且不重复的数组：engineer、entrepreneur 可兼具；undetermined 只能单独使用。依然要求两轮当前有效、维护者已确认回复、无拒绝联系和访谈记录同意。

这些校验不能证明访谈内容真实；由记录人提供原始依据，不从公开简介自动生成画像。
