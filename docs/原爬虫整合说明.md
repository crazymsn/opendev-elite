# 原 GitHub_Worker 爬虫整合说明

v0.2 已把本地原爬虫的 Python 模块重构并接入正式采集流程。早先 v0.1 仅保留旧代码并使用新 worker 入口；该状态已经改变。这里的“整合”指实际模块调用与兼容入口，不表示原实现未经修改。

```text
main.py / sponsorship-worker
  → worker.cli
  → worker.pipeline.Pipeline
      search  → src.py.fetcher.search_page
      refresh → src.py.fetcher.fetch_repository
              → src.py.userinfo.fetch_profile
  → worker.github.GitHub（REST、限流、分页与重试）
  → worker.db.Store（快照、队列、租约与事件）

旧 src.py.bootstrap.main
  → src.py.fetcher.fetch_github_repos / GitHubFetcher.run
  → 同一个 Pipeline / GitHub / Store
  → Projects_Today.csv / GitHub_User_Library_Today.csv
```

保留了旧的仓库与用户导出能力，并改为原子文件写入。兼容入口的 max_per_day 表示每日处理任务预算，batch_size 表示每次消费任务数量；旧入口按 created 日期检索，正式发现配置默认按 pushed 日期检索。不能把这些参数误解为保证返回的仓库数量。

去除了这些运行入口对 pandas、PyGithub、旧 API_KEYS、地域/族裔推断和 C++ 的依赖。原仓库中其他历史文件仍在，不能据其存在推断正式流程会执行它们。贡献者公开资料形成候选关系，仍需人工确认实际维护者，不自动推断工程师/创业者画像。

采集增加了稳定仓库 ID、完整性说明、分页截断记录、错误分类、限流退避和写入前租约校验。实际业务审核消费数据库中的版本化快照，旧 CSV 导入只提取仓库地址并重新采集，不能直接变成赞助候选。

整合验证覆盖正式 Pipeline 调用旧模块、旧 bootstrap 入口、兼容导出、日期/预算语义及上游错误处理。包内也包含 src.py 模块，安装后不依赖源码工作目录。

用户提供的远端地址为 https://github.com/Next-AGI-Org/github-worker。本轮先前通过已配置的 GitHub CLI 读取该地址得到 404；无法确认本地代码与远端最新版本是否一致。本次整合以工作区现有代码为依据，没有声称拉取或同步了该远端最新提交。
