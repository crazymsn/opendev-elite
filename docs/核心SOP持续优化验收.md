# OpenDev Elite 核心 SOP 持续优化验收

2026-09-08 基线：本机安装 0.6.1，标准 sop-2026-09-v2，schema 6。此文件区分软件能力、实际业务证据和外部联调，不能以合成测试代替产品体验或赞助到账。

## 完整目标

发现项目 → 作者/仓库资料 → 入选评估和第一轮技术复核 → 团队/自有 Agent 真实体验与第二轮筛选 → 联系 → 访谈和工程师/创业者画像 → 赞助决定 → 独立执行 Credits → 到账核对 → 复盘。

入选依据见《项目入选与排除标准》；四条范围覆盖开发者工具、真实用户 AI 工具、Agent 基础设施、Agent 调用应用。维护必须有实质提交、发布或回应等来源，更新时间只作发现信号。未知先暂缓；不以 Stars、地域、融资、团队规模或 API 封装作单独门槛。

## 已有事实与本轮缺口

本轮只读审计记录位于 artifacts/validation/sop-current-state-20260908.json：145 个项目，211 个 GitHub 实体（186 个用户、25 个组织），220 条待确认关系，81 份快照。入选判断、审核、体验、联系、访谈、决定、发放、复盘均为零。采集仍在运行，这些数字是审计时点而非固定总数。

1. 采集已整合原 GitHub Worker；提交、发布、公开响应、核心代码与文档有版本证据。候选贡献者不自动成为已确认维护者。
2. 当前待办缺少分配、补充采集、入选评估、第一轮技术复核；会让尚未评测的真实候选看似无工作。本轮补齐，沿用共同的版本与入选门槛。
3. 作者资料分散在项目中。本轮增加按稳定 GitHub ID 聚合的开发者与团队工作台；候选关系、已确认关系、访谈来源和私有业务记录权限必须分明。
4. 同一实体在多个仓库出现不能当作多个人才；组织不能当作个人。画像只取访谈记录并保留来源与日期，不从公开简介、Stars 或语言自动推断。
5. 保留默认管理员 OpenDev、首次密码 123456；由管理员创建并授权成员，公开注册关闭；保留中英文和 docker compose up -d。

## 本轮验收要求

- 新查询分页有边界、搜索字面匹配、参数严格校验；按角色过滤私有记录及其计数；匿名和 Agent 不能读人类工作台。
- 跨仓库按 ID 聚合，不通过姓名/邮箱猜测合并；授权访谈画像带原始访谈与项目来源；拒绝联系约束继续全局生效。
- 新待办和项目下一步使用共同门槛；暂缓、排除、结束项目不自动重新分配；财务对账与复盘义务仍优先。
- 浏览器验证中英文、响应式、搜索筛选分页、详情跳转、不同角色及退出后的迟到响应；新查询不修改业务事实。
- 相关回归、全量回归、安装资源与正式服务验证后交付，保留备份和回滚路径。
